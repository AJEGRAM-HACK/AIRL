# Journey scroll and swipe navigation

November 12, 2026. Frontend follow-up to `54f6d48da0668c8a7ef58ea9e2ba4c9b58081f32`, retained at `checkpoint/pre-journey-gestures-2026-11-12`. The user explicitly requested strong scroll/swipe chapter transitions.

On Journey's main stage, swipe left for next/right for previous, or swipe up/down when the content is already at the corresponding edge. Desktop wheel/trackpad input also changes chapters at the content edge. Long chapters and nested scrollable content scroll normally before navigation is eligible. A fresh gesture is required after content scrolling; trailing momentum cannot unexpectedly advance the next chapter. Buttons, rail links and existing keyboard shortcuts remain available.

The new `useChapterGestures` hook owns input thresholds, edge checks, one-chapter locking, animation phase/direction and cleanup. It routes through the existing `go`/experience URL builder, retaining universe/round/episode/saved context. It sends no API mutation or generation request. At the first/last chapter it does not wrap. Sheets and pending operations disable navigation, while links/buttons/inputs/selects/textareas/summary/editable/slider/player targets retain native behavior. Horizontal touch movement is separated from vertical reading; multi-touch/pinch is ignored by the chapter handler.

The stage responds to a deliberate pull and uses a 380 ms outgoing camera lift, followed by a 900 ms incoming depth/rotation/blur transition, reversed for backward navigation. The header, recorded decision and navigation controls stay steady. Reduced-motion preferences remove transforms/blur/animation and the exit delay while retaining gesture navigation. A persistent live region announces the chapter; gestures reset the chapter's scroll position and focus the new main stage. Camera animation is navigation feedback, never simulated production progress.

Application changes are limited to `src/components/journey/use-chapter-gestures.ts`, `src/components/journey-demo.tsx` and scoped `src/app/journey/journey.css`. `tests/browser/journey-gestures.spec.ts` exercises real Chrome wheel input and Chrome DevTools native touch-event injection; it is emulation, not a physical-phone result. Existing databases, API/auth/provider/production/video contracts and all unrelated working-tree edits remain preserved. No dependency or migration is added.
